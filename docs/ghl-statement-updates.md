# Original statements as GHL update evidence

The original-statement page under Settings > GoHighLevel > Policy updates supports contacts without a SunFire enrollment. It reparses saved source PDFs or paired Devoted workbooks/PDFs using the existing hash/row-verification service, then rechecks active imported inventory. Superseded statements and entries are excluded. It never treats carrier member IDs as MBIs.

Names and identifiers are compared only against contacts in the connected location assigned to the mapped GHL user. One agreeing full MBI plus name verifies identity. Ultimate shortened identifiers require exactly five matching trailing MBI characters, the same normalized name, and the same policy effective date. Missing identifiers, conflicting names/dates, duplicate verified contacts and truncated searches cannot produce an update. Searches are bounded name searches, not an exhaustive MBI index. Full MBIs and provider contact IDs are not returned to the browser.

For the first statement-based write path, only Active status is proposed, and only when the GHL policy date agrees with the statement, positive supported commission evidence exists, no chargeback/deduction or inconsistent identity appears in the policy group, and all entries are credited to the current owner. Agents can inspect their authorized evidence but statement writes currently require the credited owner. Missing plan names are not invented. The statement path currently does not propose plan-name, date or product-type writes.

Every send requires an exact one-contact review and separate approval, reusing the existing service-only journal, note-before-field protocol, contact-wide lock and safe uncertain-outcome recovery. Statement operation codes begin STMT_ and refer to actual visible carrier transactions. They do not create synthetic SunFire enrollments or saved SunFire links. Source file hash, all group evidence, current field metadata, contact identity and policy values are bound to the reviewed hash and rechecked before writing. The current SQL journal already authorizes owner operations; no schema change is required. Paused statement operations remain visible for review even if GHL already shows Active.

No real GHL writes are sent merely by checking statements or preparing a review. Existing statement/import records are not changed. The review branch remains separate from Main. No carrier portal recollection or scheduler is triggered.
