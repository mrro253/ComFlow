# Policy-specific commission ownership

Review branch only. The agency owner can open Commission activity, choose a client/entry, expand Change this policy's commission owner, review the existing entries and printed writer, choose the recipient and enter an explanation before saving. No real policy is reassigned merely by deploying this feature.

The rule is scoped to agency + carrier + exact carrier policy/member identifier + effective date. It does not apply to every client policy or every policy written by the same agent. This supports an agent writing a policy on a colleague's behalf while preserving the statement writer. Applications without a statement-backed policy identifier are not reassigned by this control; existing enrollment access/assignment tools remain separate.

A save atomically changes commission credit and production category on active imported entries for that policy and records a versioned rule for future entries. Printed writing-agent name, amounts, categories, effective dates, transaction keys, statement files and source hashes stay unchanged. The prior writing-user reference is preserved; if absent, the prior credited producer becomes the writing-user reference. Future imports preserve their own original writer/classification while applying the selected recipient through a common database insert trigger, covering single-PDF and paired Devoted imports. Renewals, chargebacks and corrected replacement rows with the same policy key follow the rule. A new effective date/carrier/policy identifier requires its own choice.

The control is agency-owner-only. Active direct commission recipients with an owner/agent role are eligible. Captive production retains its principal-based credit model: choose the principal rather than redirecting carrier commission to the captive writer. A unique configured production category is required. Inactive or cross-agency recipients are rejected. A saved recipient becoming unavailable blocks future imports rather than silently crediting the writer again.

Existing earnings, or any compensation lock for the same carrier/member, block reassignment. This intentionally conservative lock check protects policy versions whose compensation mapping cannot be safely changed here. Compensation persistence shares an advisory lock and rejects stale ownership plans. Pending GHL field/note work, uncertain contact creation and live import processing are protected before ownership changes. The table and RPCs are service-only with owner and tenant checks; the stale-review hash binds active source rows and rule version. All changes retain the prior assignments and required explanation in the append-only audit trail. Choosing a previous recipient is an explicit new version, not history deletion.

Changing a ComFlow commission owner does not transfer money, modify carrier portal records, reassign SunFire enrollment access, move a GHL contact or inherit another agent's GHL link. Existing GHL receipts remain with the original actor; fresh identity/assignment checks may hold later processing. There is no GHL write or backlog queue added by an ownership edit. Agents' own financial dashboards, commission lists and client-history totals use credited ownership rather than counting preserved writer attribution as a second commission recipient. Captive production views and authorized management views retain their existing scope.

Validation includes owner/agent/cross-agency permissions, stale-review rejection, unchanged source amounts/writer, isolated policy/carrier boundaries, renewals and chargebacks, the real import RPC with GHL queue credit following the recipient, pending GHL blocking, unavailable recipients, compensation locks and existing earnings. All fixtures roll back in the isolated database. The local schema migration adds no rules and moves no real commissions; real changes occur only when the owner selects a policy and saves the reviewed choice.
